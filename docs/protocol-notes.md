# 协议事实清单

只记录**事实**：接口地址、字段名、固定值、编码规则、响应特征。
来源一律为「线上观测」（页面脚本、请求录制、实际提交）。

---

## 1. 入口页面

- 入口为问卷页 GET，返回服务端渲染的 HTML。
- 偶发返回不含题目的空壳页，需要重试。
- 页面内可解析出：问卷标识、题目区、选项区、提交表单。

来源：线上观测。

## 2. 题目结构（HTML）

| 结构 | 含义 |
|---|---|
| `div.field`（含 `ui-field-contain`） | 一道题的外层容器 |
| 容器的 `type` 属性 | 题型编码，见下表 |
| `div.topicnumber` | 题号文本，形如 `4.` |
| `div.topichtml` | 题干 |
| `div.field-label` | 旧版题干容器 |
| `div.ui-radio` / `div.ui-checkbox` | 选项行 |
| 选项内 `div.label` | 选项文本 |
| `span.req` 或容器 `req="1"` | 必答标记 |
| `table.matrixtable` | 矩阵题行列结构 |
| `div.scale-rating ul li a[val][title]` | 量表题档位（`val` = 分值，`title` = 文案） |
| `select option` | 下拉题 |

题型编码（容器 `type` 属性）：

| 编码 | 题型 |
|---|---|
| `1`、`2` | 填空 |
| `3` | 单选 |
| `4` | 多选 |
| `5` | 量表 |
| `6` | 矩阵 |
| `7` | 下拉框 |
| `8` | 滑块 |
| `11` | 排序 |

来源：线上观测。

## 3. 答案串（answer_blob）编码规则

| 语法 | 含义 |
|---|---|
| `题号$内容` | 一题的答案 |
| `}` | 题与题的间隔 |
| `\|` | 多选的选项序号间隔，如 `2$1\|3` |
| `^` | 多空填空的间隔，或「选项 + 附加文本」的间隔 |
| `!` | 矩阵题行列分隔，如 `4$1!2` |
| `,` | 矩阵题多行分隔，如 `4$1!2,2!3` |
| `-3` / `(跳过)` | 该题被逻辑跳过 |

来源：线上观测（对照提交前后编码差异）。

### 3.1 内容转义

| 原字符 | 替换为 |
|---|---|
| `!` | `！` |
| `^` | `ˆ` （U+02C6） |
| `$` | `ξ` |
| `}` | `｝` |
| `\|` | `¦` （U+00A6） |
| `<` | `＜` |

来源：线上观测。

## 4. 提交接口

- 页面表单：`<form action="https://<host>/joinnew/processjq.ashx?shortid=<token>">`
- 方法：POST，`application/x-www-form-urlencoded; charset=UTF-8`
- 请求体：`submitdata=<answer_blob>`；触发验证时还会带 `sceneId`、`captchaVerifyParam`

查询参数：

| 参数 | 含义 | 来源 |
|---|---|---|
| `shortid` | 问卷标识 | 链接或页面 |
| `jqnonce` | 一次性随机串（UUID） | **页面下发** `var jqnonce` |
| `jqsign` | 校验串 | 由 `jqnonce` 与 `ktimes` 计算，见第 5 节 |
| `ktimes` | 交互次数（小整数） | 客户端累加 |
| `starttime` | 页面渲染时刻，`YYYY/M/D HH:MM:SS` | 页面隐藏域 |
| `submittype` | 提交类型，正常提交为 `1` | 固定 |
| `rn` | 随机数 | 客户端 |
| `source` | 来源标识，可不传 | 客户端 |

来源：页面脚本 `joinnew/js/jqmobo2.js` 与实测提交。

## 5. 校验串算法（已验证）

页面脚本中的实现等价于：

```text
key = ktimes % 10;  若 key == 0 则 key = 1
sign = 对 jqnonce 的每个字符做 charCode ^ key，再拼回字符串
```

即「用 ktimes 的个位做异或」，不是哈希、不是加密。

本仓库实现：`protocol/wjx/seal.py` 的 `xor_ktimes`。
默认方案已启用该策略（`channel.seal_mode = "xor_ktimes"`）。

实测结论：带上正确校验串后，服务端不再返回参数错误，而是进入验证环节
（见第 6 节），说明校验串与参数集是正确的。

## 6. 响应判定

| 响应 | 含义 |
|---|---|
| `10` | 成功（线上观测，建议多例复核） |
| `22，请完成验证。` | 已受理但要求完成人机验证 |
| 含「已停止 / 已结束 / 未开放」 | 问卷不可提交 |
| 含「次数 / 上限」 | 触达次数或份数上限 |
| 其他短响应 | 结果不明，进复核队列 |

`22` 属于**需要人工验证**的情形：协议层无法自动通过，任务应暂停并提示，
而不是重试刷量。

来源：实测提交响应。

## 7. 观测到的限制

| 限制 | 表现 | 应对 |
|---|---|---|
| 人机验证 | 返回 `22，请完成验证` | 暂停任务，交人工或走浏览器通道 |
| 单出口短时高频 | 静默丢弃或提示频率异常 | 降速 + 换出口 |
| 极短停留时长 | 判定异常 | 时长与真实间隔自洽，禁止事后改写 |
| 同一出口相同画像 | 提示重复 | 出口 × 画像打散 |
