按「数据能不能用」排序，不按「填了多少份」排序。

### V1（下一步）

| 需求 | 说明 |
|---|---|
| 可行性体检 | 解析时判定：登录、微信、关闭、题量、逻辑题数 |
| 人口学配额 | `quota.targets`：题号 → 选项占比，生成时按配额纠正 |
| 开放题文本 | 长度分布、去重、语义相关，避免模板化 |
| 批次一致性 | 同 IP 段/同画像的答卷打散，避免整批看起来像同一人 |
| 质量门 | 发送前批量体检：α/KMO/直线作答/过快作答，不达标拒跑 |
| 导出 | CSV + 数据字典（题号 ↔ 变量名） |

### V2

| 需求 | 说明 |
|---|---|
| 目标数据反推 | 给一份目标数据集或描述统计，反解生成参数 |
| 显著性目标 | 按「显著项数区间」生成，而不是追求全显著 |
| SEM 拟合 | 需要联合构造，成本较高 |
| 多任务队列 | 排队、优先级、失败任务重跑 |

### 明确不做

| 不做 | 原因 |
|---|---|
| 微信环境 / 登录态问卷 | 协议层无法可靠模拟 |
| 验证码自动破解 | 只提供「暂停 + 提示人工处理」的兜底 |
| 鼠标行为模拟 | 协议层没有页面可见性概念，模拟无意义 |
| 地区筛选 | 由外部提取链接决定，程序不管 |

## 「看起来合理」的三条硬标准

1. **不要太一致**：矩阵题不许直线作答；选择题有形状倾向（左偏/右偏/居中/双峰），不是均匀随机。
2. **不要太整齐**：提交时刻按 24 小时活跃权重分布，份间间隔对数正态（重尾），不是等距。
3. **不要太完美**：α 目标 0.70~0.92（不追 0.98）、显著项按区间、单因子解释占比 ≤ 40%。

## 验收清单

- [ ] 解析任意公开问卷，题号/题型/选项与页面一致
- [ ] `verify` 输出的答案串与手工抓包逐字段可对
- [ ] 提交成功后台可见，失败原因分类正确
- [ ] 关闭出口链接时给出明确提示，而不是静默失败
- [ ] 同一 seed 重跑得到完全相同的答案
- [ ] 200 份跑完，α/KMO/直线作答三项全部达标
- [ ] 任务中断后可续跑，已成功份数不重复
